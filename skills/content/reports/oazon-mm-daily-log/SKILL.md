# 从 Mattermost 生成个人日报

把一天的 Mattermost 消息收敛成本人视角的日报：按项目分组，每条写清动作与结果，附工时，默认合计约 8h。流程是取数、归纳、出草稿；用户要求写入时，再走备份、diff、确认、落盘。

## 默认口径

- 日期：Asia/Shanghai 的今天；用户指定历史日期时按指定日。
- 身份：浏览器登录态的 `users/me`，无需询问。
- 范围：只写本人经手、拍板或驱动 bot 完成的工作；被抄送、他人自行完成的不算。
- 工时：默认约 8h，信息不足时如实说明，不编条目凑数。
- Mattermost 全程只读，不发消息、不修改内容。

## 抓取

先运行 `opencli doctor`，确认 daemon 与 extension 已连接，且浏览器已登录 mm.oazon.com。工作目录放会话 scratchpad，不落进用户项目：

```bash
python3 scripts/fetch_mm_day.py --out <工作目录> [--date YYYY-MM-DD]
```

主要产物：

- `summary.txt`：频道分布、时间区间和发言人排行。
- `mine.txt`：本人发言、@本人消息及所在 thread，是主要输入。
- `ch-NN-*.txt`：分频道全文，按需补上下文。
- `posts.json`：全量结构化消息，用于追溯原文和真实 Boost 链接。
- `meta.json`：日期、身份、频道和消息统计。

先核对登录身份、日期、工作时段和总量；该账号通常约 1000–1400 条/天。仅在上午缺失、数量异常或分页可疑时，完整读取 `references/mattermost-api.md` 排查日界线与翻页。

## 归纳与草稿

1. 读 `summary.txt` 掌握主线和时间跨度。
2. 分段完整读完 `mine.txt`，不能只读开头；结论不清时再查对应频道全文。
3. 按当天实际主线合并项目，优先复用 `daily.md` 近期项目短名。
4. 草稿前读取 `references/report-format.md`；长样例、反例和工时区间都在其中，不在本文件重复。
5. 每条都要能回溯到原始消息，只保留本人的判断、执行和结果。

输出格式：

```markdown
- **<项目短名>**
    - <做了什么 + 关键结果>（Xh）
- **其他**
    - <零散事项>（Xh）
```

硬性要求：

- 项目名不带时长；同一项目不拆成多个大项。
- 子条目正文不超过 30 字，一条只写一件事，工时最小 0.5h。
- 说人话，不写函数名、文件名、参数名、commit hash 或卡片 id。
- 保留台数、条数、比例和前后对比等数字，每条都要有结果或结论。
- Boost 卡片链接套在现有文字上；从 `posts.json` 取真实 URL，不使用脱敏的 `[url]`。
- 草稿可附“明日待跟进”，但不计工时，也不写进 `daily.md`。

给出草稿后等待用户确认；可说明有意排除的他人工作或纯抄送事项。用户只说“整理日报”时到此为止。

## 写入 daily.md

仅在用户明确要求“写入”或“补到 daily.md”时，完整读取 `references/daily-md.md`。目标优先使用 Windows 路径 `D:\obsidian\xnote\WorkLog\Oazon\daily.md`；找不到时再定位 Oazon 库，不能误用 DigiFinance 那份。

顺序不可颠倒：

1. 备份原文件到会话 scratchpad。
2. 在 scratchpad 拼出候选新文件，不直接改原文件。
3. 生成统一 diff 给用户看，并用命令验算工时符合约定值。
4. 即使用户已说“写入”，也先展示 diff；无需重复询问是否要写，但必须等用户确认内容。
5. 用户确认后覆盖写入，再回读插入位置核对。

落盘时保持 4 个空格缩进、全角 `（Xh）`、裸行日期 `2026.08.20`（年.月.日，月/日补前导零），只新增一个日期块，不改写或重排历史内容。

## 完成检查

- 身份、日期、时区、消息量和工作时段合理，`mine.txt` 已完整读完。
- 只写本人，每条有原始依据，没有推测或编造。
- 每条有工时且正文不超过 30 字，合计约 8h；逐项验算而非目测。
- 项目名简短，正文无技术标识符，关键数字和真实 Boost 链接仍在。
- 抓取产物仅留本地，不上传外部服务；脚本和文档不保存 token、密码或 cookie。
- 写入时已备份、展示 diff、获得用户确认，并回读核对。
